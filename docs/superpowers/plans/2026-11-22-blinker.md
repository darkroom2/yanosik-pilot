# Blinker Firmware Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a minimal interactive nRF52 sketch and Unity tests for its RGB-and-button behavior.

**Architecture:** Keep GPIO handling in `firmware/blinker/src/main.cpp` and put the Arduino-independent state machine in a private PlatformIO library shared with the Unity tests. Use `millis()` timing and per-button debounce; add no external dependencies.

**Tech Stack:** PlatformIO, Arduino framework, Nordic nRF52 DK target.

**Spec:** `docs/superpowers/specs/2026-11-22-blinker-design.md`

## Global Constraints

- Use the existing PlatformIO Arduino environment (`nrf52_dk`).
- Buttons are active-low with `INPUT_PULLUP`.
- RGB LED channels are active-low: red P0.17, green P0.18, blue P0.19.
- In the `nRF52DK` Arduino variant, those physical pins map to digital pins D2/D3/D6/D7/D8 respectively.
- Button 1 (P0.13) advances through red, green, and blue; button 2 (P0.14) pauses or resumes blinking.
- Keep blinking non-blocking and the program limited to this behavior.
- Use PlatformIO Unity host tests in `host-test-windows` (`windows_x86`) and `host-test-linux` (`linux_x86_64`); no board is needed for logic tests.

## Review Focus

- Active-low LED output: manually verify the selected channel alone illuminates and all channels are off during pause through the ESP32/SWD hardware workflow.
- Active-low button input and debounce: test that a stable press acts once and bounce/holding does not repeat an action.
- Blink timing and pause/resume: test that blinking changes at 500 ms intervals, pause forces off, and resume keeps the selected color.
- Responsiveness: manually verify both buttons remain usable while blinking.
